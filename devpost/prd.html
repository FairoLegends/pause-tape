PAUSE TAPE

Product requirements. Record a tape to your future self when you stop; play it back when you return so you know exactly what to do next. First real user: pausing NO SIGNAL until 10 January 2027.

RECORD

prd.md › Features and Behavior › Recording a Tape

Camcorder viewfinder: ● REC with a running timer at the top. Everything on one screen. Scanlines stay thin so typing is comfortable.

"Six separate steps feel slow, both in use and in the demo video."
  • Tape label: project name*, return date*.
  • Message: where I stopped · first step when I come back (~10 min)* · what I'm still unsure about · why this project matters to me.
  • * required: "without them the tape can't work: no label, no reminder, no step for the timer."
  • Date choices start from today. Today is allowed.
  • ■ STOP saves.
  • Incomplete: not saved; empty required fields marked red with "TAPE INCOMPLETE"; typed answers kept.
  • Optional answers empty: allowed. "I don't want to be forced to fill in something that doesn't exist."
  • Past dates: can't be picked.
  • ● REC opens the Record Screen with ● REC indicator and running timer.
  • Name, date, and all four questions on one screen.
  • Past dates can't be selected; today can.
  • ■ STOP with name, date, first step → saved, "TAPE SAVED" shows.
  • ■ STOP with any of those empty → not saved, red fields, "TAPE INCOMPLETE", typing preserved.
  • Saving works with optional answers empty.

TAPE SAVED + .ICS

prd.md › Features and Behavior › Calendar Reminder (.ics)

A brief "TAPE SAVED" screen with "Add to calendar (.ics)", then back to the shelf where the new tape appears.

  • The button provides a calendar file for the return date.
  • The reminder lands in the phone or laptop calendar.
  • All-day event, named after the project. Description holds your first step, with a morning alarm at 08:00 WIB, so the reminder alone tells you what to do.
  • Return date today → the new tape is READY right away (needed for the demo).
  • Calendar skipped: the tape is still saved; the file is optional.
  • Why: "When the reminder pops up on my phone, I already know my first step before even opening the app."
  • "Add to calendar (.ics)" produces an .ics file.
  • Opening it adds an all-day event on the return date, named after the project.
  • The event description contains the first step.
  • The event has an alarm at 08:00 WIB on the return date.
  • Leaving the screen returns to the shelf with the new tape shown.

EARLY PLAY

prd.md › Features and Behavior › Early Play
"So it still feels like a message from the past, but doesn't block me if I can come back sooner."
  • Pressing ▶ on a locked tape asks for confirmation first.
  • VCR-style: "TAPE DUE 10 JAN 2027. PLAY EARLY?" (the tape's own date) with ▶ PLAY and CANCEL.
  • ▶ PLAY: full playback, first step, timer, minutes, as normal.
  • CANCEL: back to the shelf, still locked.
  • ▶ on a locked tape shows "TAPE DUE [date]. PLAY EARLY?" with ▶ PLAY and CANCEL.
  • ▶ PLAY plays the tape normally.
  • CANCEL returns to the shelf; tape stays locked.

PLAYBACK

prd.md › Features and Behavior › Playback

A brief blue VCR screen, then the answers one by one, each with a short VHS glitch, each staying on screen. ▶ PLAY counter in a corner. Scanlines at their strongest.

"So it feels like watching an old recording of myself, not reading a boring form."
  • Order: the message answers first, first step last: "it's the most important part."
  • ▶▶ skips the rest: "I don't want to be forced to wait if I already remember."
  • Empty optional answer: flashes briefly as a blue "NO SIGNAL" screen.
  • Skipped: everything shows at once, including the first step, and the timer starts.
  • ▶ on a READY tape → brief blue VCR screen → Playback.
  • Answers appear one at a time with glitch; earlier ones stay.
  • ▶ PLAY counter runs in a corner.
  • Empty optional answer shows briefly as "NO SIGNAL".
  • First step is the last thing to appear.
  • ▶▶ shows everything including the first step; timer starts.
  • Effects visibly stronger than on the Record Screen.

FIRST STEP + TIMER

prd.md › Features and Behavior › First Step and Timer

The moment the first step appears, a 10:00 countdown starts beside the "I'm back on it" button.

"The 10-minute timer is a nudge to start, not a punishment. If I needed 13 minutes, that still means I made it back, so the number has to be honest."
  • Countdown from 10:00.
  • Minutes are counted from pressing ▶, not from when the timer appears.
  • Overtime: after 0:00, it keeps counting as "+01:23" in a different color. The button still works.
  • App closed while the timer runs: nothing is recorded; the tape stays READY without minutes and plays again from the start. A locked tape played early returns to locked.
  • Countdown starts the moment the first step appears.
  • "I'm back on it" is visible alongside the timer.
  • After 10 min, overtime "+mm:ss" in a different color; button still works.
  • Closing the app mid-timer → reopening shows the tape still READY, no minutes; it plays from the start.

BACK ON IT · 4 MIN

prd.md › Features and Behavior › First Step and Timer

A brief result screen, then back to the shelf, where the tape's label now shows the minutes.

  • Shows "BACK ON IT · N MIN". N includes any overtime (e.g. 13 MIN).
  • Completed tape: stays on the shelf as proof. "If it's deleted, the proof disappears too."
  • Pressing "I'm back on it" shows "BACK ON IT · N MIN", N = minutes since ▶.
  • Back on the shelf, the label shows the minutes.

REPLAY

prd.md › Features and Behavior › Replaying a Completed Tape
"Replaying is for remembering again, not returning from a pause."
  • A completed tape plays its answers again.
  • Pausing the same project again = record a new tape.
  • No timer, no "I'm back on it" on replay.
  • The original minutes are never overwritten.
  • Replaying plays the answers as in Playback.
  • No timer and no button appear.
  • Label minutes never change after the first time.
